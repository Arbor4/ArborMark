## 架构

- **编辑态（WYSIWYG）**：Milkdown（ProseMirror）。在渲染态直接编辑文本/标题/引用/列表/表格/代码/公式/图表。
- **源码态**：CodeMirror 6，`wysiwyg=false` 关闭混合装饰与语法高亮 → 纯文本。
- **预览态**：markdown-it + KaTeX + highlight.js 只读渲染。
- 旧版 `src/renderer`（原版衍生 vanilla JS）作为「原版实现」参考：即时编辑、偏好设置项、emoji 映射。

## 实施计划（逐项完成）

### A. Milkdown 渲染与原位编辑

1. **引用**：CSS 改为经典风格——仅左边框+缩进，去背景卡片/圆角；嵌套靠边框+缩进。
2. **Emoji**：自研插件，原生 Unicode 字符（离线、1.2em），emojilib 全别名映射（thumbsup→👍）；替换 twemoji CDN。
3. **Mermaid**：node view 读 viewBox 计算固有尺寸，保持宽高比，max-height 约束+居中；主题配色联动；attrs.value 单一数据源。
4. **代码块**：node view = 语言标签+复制按钮+highlight.js 高亮（ viewing ）/ 点击进入原位纯文本编辑。
5. **表格**：选中/悬停显示增删行列控件（+行/+列/删除行/删除列/对齐）。
6. **公式**：math_inline/math_block node view，点击切换 TeX 编辑，失焦/Esc 重新渲染 KaTeX。
7. **HTML**：html_block/html_inline 节点，DOMPurify 净化渲染，点击编辑源码。
8. **Front Matter**：remark 识别首部 `---` YAML，渲染为样式化源块，序列化回 `---`。
9. **mark/sup/sub**：remark + ProseMirror mark，==高亮==/^上标^/~下标~。
10. **GitHub 提示块**：\[!NOTE]/\[!TIP]/\[!IMPORTANT]/\[!WARNING]/\[!CAUTION] 渲染为彩色提示框。
11. **flow/sequence**：优雅降级为带标签代码块（不引入额外重型库）。

### B. UI

12. **右键菜单**：验证 + 上下文增强（表格/代码/公式专属项）。
13. **源码模式**：复核纯文本。
14. **全局搜索**：中间偏上（\~16vh），结果区留足空间。
15. **大纲**：复核折叠/展开 + 按钮栏。
16. **偏好设置**：对照原版补全并接线——Markdown 语法开关（内联公式/高亮/上下标/图表/提示块/HTML/emoji）、智能标点、缩进/换行、编辑器（自动配对/拼写/自动换行/缩进宽度）、图片（相对路径）、外观（工具栏/大纲高亮）。语法开关变更触发编辑器重挂载。

- 演示文件逐项：渲染正确 + 渲染态可继续编辑 + 编辑后源码正确回写。

## 关键技术坑（维护必读）

1. **`$remark` 工厂层级**：`$remark(id, factory)` 中 `factory(ctx)` 必须返回「remark 插件函数」
   （`() => transformer`），而非 transformer 本身。带参的 `remarkInlineExt(opts)` 返回 transformer，
   故须写 `$remark(id, () => () => remarkInlineExt(opts))`，少一层 `() =>` 会静默失效。
2. **mark 的 `toMarkdown` runner 不能返回值**：`state.withMark(...)` 返回 state（truthy），
   若 runner 用箭头表达式体返回它，序列化器会跳过文本内容（输出 `====` 丢字）。
   必须用块体 `{ state.withMark(mark, "mark"); }`（无 return），与 strong 一致。
3. **gfm `singleTilde`**：remark-gfm 默认 `singleTilde:true` 会把 `~下标~` 当删除线。
   须 `ctx.set(remarkGFMPlugin.options.key, { singleTilde:false })` 把单波浪线留给下标插件。
4. **自定义 mdast 节点回写**：mark/sup/sub/yaml/alert 需在 `remarkStringifyOptionsCtx.handlers`
   注册 handler（`containerPhrasing`/`containerFlow`），否则 remark-stringify 不识别。
5. **HTML 成对标签合并**：remark 把 `<kbd>Ctrl</kbd>` 拆成 html("<kbd>")+text+html("</kbd>")，
   分别渲染会各自闭合（空框）。须按源码偏移把成对标签合并为单个 html_inline 再净化渲染。
6. **node view 数据源**：图表/公式块/HTML/Front Matter 用 `attrs.value` 单一数据源 + textarea
   编辑 + `setNodeMarkup`，避免 contentDOM 与 attrs 不一致导致编辑丢失。
7. **details 合并必须在 commonmark 之前**：commonmark 的 remark 插件会把块级 html 转成
   paragraph，后注册的 remarkHtmlSplit 拿不到碎片。解决：`detailsRemark`（产出自定义
   `html_details` 节点类型）在 `.use(commonmark)` 之前 `.use()`；custom 类型不被流水线改写。
8. **mermaid 实时编辑防抖**：输入中途语法不完整会抛错——保留上一帧正确 SVG，仅显示
   「语法待完善…」徽标；完成/Esc/外部点击时才做最终渲染。SVG id 序号防竞态过期结果覆盖。

## 已知限制（后续可增强）

- flow/sequence 经 mermaid 转换渲染，个别冷僻语法（如 sequence 的 `title`/autonumber）可能降级报错。
- 启动命令行传文件时 React 前端未消费 `_options.targetFile`（旧版桥接遗留路径），需手动打开；
  会话恢复指向已删除文件时会落到该目录的 Untitled.md。
- 智能标点/自动配对/图片路径等偏好已持久化，部分深度接线（序列化/插入流程）待后续完善。
